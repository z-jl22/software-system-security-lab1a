## 1. macOS 安装与运行

在本项目目录打开终端。建议 macOS 13 或更新版本，Python 3.9 或更新版本。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py
```

本机已建立 `.venv` 并安装 PySide6 6.10.3，可以直接执行第三行。也可以双击 `launch.command`。新电脑先执行 `chmod +x launch.command`。libpcap 由 macOS 提供，无需安装 Windows Npcap。

启动后点“加载教学样例”，即可在不授权的情况下验证所有离线功能。教学样例明确标记为人工构造，不是网络捕获证据。`samples/teaching.pcap` 含 15 包；`samples/loopback.pcap` 用于 macOS DLT_NULL 链路类型测试。

## 2. 真实抓包：推荐先用 CLI 验证

macOS 的 `/dev/bpf*` 默认只允许 root 访问，普通 GUI 无权打开设备时会提示错误。列出网卡不等于已获得抓包权限。

终端一，在项目目录执行：

```bash
sudo /usr/bin/python3 main.py --capture lo0 --filter 'tcp port 8080 or icmp or icmp6' --seconds 15 --output local.pcap
```

终端二，在 15 秒内执行：

```bash
.venv/bin/python tools/local_traffic.py
```

然后用普通用户打开捕获结果：

```bash
.venv/bin/python main.py --read local.pcap
```

此方案仅将无第三方依赖的命令行抓包部分以管理员身份运行，图形界面仍以普通用户身份运行。命令行可 Ctrl+C 提前停止并保存。若系统没有 `/usr/bin/python3`，使用已安装的 Python 3 解释器绝对路径替换它。

若希望在 GUI 中直接实时抓包，可安装 Wireshark 官方 macOS 安装包中的 ChmodBPF 组件以授予 BPF 访问权限，再以普通用户启动本程序。程序不会自行修改 BPF 权限。已经具备 BPF 权限时，选择 lo0、输入 BPF、点击“开始抓包”，再运行流量生成器；停止后可保存。抓本机回环服务选 lo0，观察无线网络选 en0 并确认实际接口。

自动真实验证脚本 `python3 tools/verify_live.py` 会请求 macOS 管理员授权，仅捕获 lo0 上自身本地 HTTP 测试端口和 ICMP，持续 8 秒，不更改设备权限。结果位于 `output/verification/live-result.json` 与 `live-loopback.pcap`。脚本只能在本机图形登录会话下使用。

## 3. 界面操作

1. 抓包前选择网卡并设置“捕获过滤 BPF”。这是 libpcap 过滤，会影响实际收到哪些包。
2. 在数据包列表选择一行，在下方查看协议树与十六进制数据。
3. 在“显示过滤”中输入表达式并点应用。它只影响列表，不删除已存数据。
4. 选择 TCP/HTTP/TLS 包，点“追踪选中 TCP 流”，查看双向包及段载荷。此操作会清空显示表达式并切换至该流。
5. “取消流筛选”恢复整个会话；显示过滤仍按当前表达式执行。
6. “保存全部 PCAP”保存会话全部包，包含被显示过滤隐藏的包。

支持的显示过滤示例：

```text
http
ipv4 and tcp
ipv6 and icmp6
(tcp or udp) and not port 53
src host 192.0.2.10 and dst port 8080
dns or arp
```

支持 `not`、`and`、`or`、括号；优先级为 not > and > or。不支持隐式 AND，不支持完整 Wireshark 语法。捕获过滤使用 libpcap BPF 语法，可写 `tcp port 8080`；显示过滤需要 `tcp and port 8080`。HTTP 使用载荷起始行识别，不把 80 端口直接当作 HTTP。`tcp` 可匹配包含 TCP 底层的 HTTP/TLS 包。

## 4. 验证与证据

```bash
mkdir -p tmp
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tools/verify_gui.py
.venv/bin/python main.py --inspect samples/teaching.pcap
/usr/sbin/tcpdump -n -r samples/teaching.pcap
```

`tools/verify_gui.py` 使用 Qt 离屏模式执行真实窗口操作、断言结果并导出截图，不需要控制桌面。视频由这些真实 GUI 状态组成，属于自动化功能演示，不声称是连续桌面录屏；最后展示实际捕获 PCAP 的回放。

当前已完成真实 libpcap 抓包验证：370 包，其中 TCP 266、HTTP 52、ICMP 52。捕获端口为动态本地端口 65044。此处的 TCP 数量仅计最上层被标记为 TCP 的包，不含被标记为 HTTP 的 TCP 包。TCP/IP 分层过滤则按协议树匹配。

GUI 原始字节上限 64 MiB，包数上限 20000，抓包线程队列上限 4096；达到会话上限自动停止接收。包对象、解析结果与队列本身还有额外内存开销。显示的队列丢弃数不是内核丢包数。高吞吐性能未测试。

## 5. 已知限制和实验答辩

- 未实现 TCP 字节流重组；“流追踪”是双向连接归组及按捕获顺序查看段载荷，不是消重后的完整应用层消息。
- 未实现 IPv4/IPv6 分片重组。需要重组的分片不会误当成 TCP 头解析。
- HTTP 仅识别单个 TCP 段起始的 HTTP/1.x 请求/响应；跨段头部、HTTP/2、HTTP/3 不完整支持。
- TLS 仅做记录头特征识别，不验证完整握手，不解密 HTTPS。样例 TLS 记录仅用于特征识别测试，不是有效完整握手。
- DNS 解析头部与第一个问题，支持压缩名称指针并检测循环，不完整解析回答资源记录；不支持 TCP DNS 消息重组。
- 不支持 PCAPNG、进程归属关联、内核丢包统计和吞吐率保证。
- TCP 端点复用用 SYN、FIN/RST 和 120 秒空闲间隔做有限区分，不是完整 TCP 状态机。

答辩前建议自己逐步阅读 `sniffer/pcap.py` 的 ctypes 数据结构与 API 声明、`sniffer/parser.py` 的偏移/长度计算、`sniffer/filters.py` 的递归下降解析、`sniffer/streams.py` 的双向端点归组。代码和报告由 AI 辅助生成，应理解并按实际学习过程调整，不应把自动生成过程描述成个人独立实现。
